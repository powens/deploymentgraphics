# Contributing

## Setup

You need Node 22.6 or newer and pnpm 11.21 or newer (below 12). The range is
pinned in `package.json` under `devEngines`, and pnpm downloads a matching
version when yours falls outside it.

```sh
pnpm install
make serve        # demo viewer with live reload
```

`make serve` serves `static/` over a freshly built `dist/bundle.js` and
reloads on change. Domain terms used in the code (Placement, Placed, Resolve,
Template box, centre-pivot, Controls) are defined in [CONTEXT.md](CONTEXT.md).

## Checks

Run these before opening a pull request. CI runs the same set.

```sh
pnpm lint
pnpm type-check
pnpm test                 # vitest
pnpm gen:presets:check    # generated presets match static/data/
pnpm convert:40kdc:check  # combined.yml matches the vendored 40kdc JSON
pnpm build                # demo bundle -> dist/bundle.js
pnpm build:lib            # publishable lib/
```

Tests live next to the code (`src/**/*.test.ts`, `scripts/*.test.mjs`,
`static/*.test.js`) and run under Node by default. A test that needs the DOM
opts in with a `// @vitest-environment happy-dom` comment.

## Generated files

Some files are build output that happens to be committed. Edit their source
and regenerate instead of editing them by hand.

| File | Source | Regenerate with |
| --- | --- | --- |
| `src/presets/*.ts` with a "Generated by" header | `static/data/*.yml` | `pnpm gen:presets` |
| `static/data/terrain/combined.yml` | vendored 40kdc JSON | `pnpm convert:40kdc` |
| `assets/sample.svg` | the renderer | `pnpm build:lib && node --experimental-strip-types scripts/render-sample.mjs` |

`combined.yml` is produced purely from the vendored 40kdc data. Fix bad terrain
upstream, never in the vendored files. `make update-terrain` pulls and converts
fresh 40kdc data but does not run `pnpm gen:presets`, so run that afterwards.

## Public API

Only what `src/index.ts` and `src/presets/index.ts` export is public. Layout
ids (`buildConfig({ layout })`) are part of that API, so renaming one needs a
CHANGELOG entry with the old and new ids.

## Commits

Use [conventional commits](https://www.conventionalcommits.org/) with a scope,
for example `fix(placement): ...` or `feat(viewer): ...`. End the subject with
the issue number the commit closes, `(#123)`.
